# Fine-tuning Llama-3.3-70B (QLoRA)

`finetune_llama.py` trains one LoRA adapter per step on the 4-bit `meta-llama/Llama-3.3-70B-Instruct`:

| Task | Input prompt | Model answer |
|---|---|---|
| binary | binary prompt V3 | `{"binary": 1, "label": "eval"}` |
| appraisal | appraisal prompt V2 | `{"label": "judgment"}` (evaluative sentences only) |

These are the prompts that won the zero-shot selection (`../Prompting`). The fine-tuned model can therefore be compared directly
with zero-shot Llama on exactly the same 125 held-out sentences.

## Data

The same 70 / 30 split as the prompting experiments. **Ambiguous sentences (27) are removed everywhere.**
The 70% is split 85 / 15 into train / val, stratified by class and domain. Saved in `outputs/ft_split.csv`.

| Part | Sentences | Non-evaluative | Evaluative | Affect | Judgement | Appreciation |
|---|---|---|---|---|---|---|
| Train | **244** | 100 | 144 | 27 | 64 | 53 |
| Val (epoch selection) | **44** | 18 | 26 | 5 | 12 | 9 |
| Test = held-out 30% | **125** | 54 | 71 | 9 | 33 | 29 |
| Removed (ambiguous) | 27 | – | 27 | – | – | – |
| **Total** | 440 | 172 | 268 | | | |

Training data is balanced by **oversampling** the smaller classes (val and test are never changed):
- binary: 244 → **288** examples (144 non-evaluative + 144 evaluative)
- appraisal: 144 → **192** examples (64 Affect + 64 Judgement + 64 Appreciation)

## Training setup

4-bit NF4 (double quantization, bf16 compute), LoRA r = 16 on the attention layers
(65.5 M trainable parameters, 0.09%), 3 epochs, learning rate 1e-4, gradient accumulation 8,
loss only on the answer tokens, one 48 GB GPU. After every epoch the model is scored on val, and the best epoch is kept:

| Task | Val macro-F1 epoch 1 / 2 / 3 | Kept |
|---|---|---|
| binary | 0.727 / **0.747** / 0.646 | epoch 2 |
| appraisal | 0.471 / 0.728 / **0.795** | epoch 3 |

## Test (held-out 30%, 125 sentences)

Two steps, like a real annotation run: the binary adapter labels every sentence, then the appraisal
adapter labels the sentences step 1 called evaluative. Zero-shot = the same base model and prompts without adapters.

| Step | n | Zero-shot macro-F1 | Fine-tuned macro-F1 | Zero-shot κ | Fine-tuned κ | p (randomization) | p (McNemar) |
|---|---|---|---|---|---|---|---|
| 1 binary | 125 | 0.807 | **0.833** | 0.616 | **0.668** | 0.525 | 0.524 |
| 2 appraisal (model-evaluative) | 63 / 79 | 0.554 | **0.558** | 0.281 | **0.333** | – | – |
| Combined (none / affect / judgment / appreciation) | 125 | 0.568 | **0.602** | 0.454 | **0.516** | 0.531 | 0.720 |

- Fine-tuning helps mainly on **recall** of evaluative sentences (0.775 → 0.915) and on **Judgement** (F1 0.571 → 0.667).
  Affect gets worse (0.533 → 0.444).
- **None of the differences is statistically significant.** Step 2 has no paired test because each setup labels different sentences.
- The zero-shot numbers here differ slightly from `../Prompting/Heldout_pipeline` (binary 0.807 vs 0.799) because the
  base model runs here in 4-bit with transformers, and there through Ollama.

## Files

| File | Content |
|---|---|
| `finetune_llama.py` | `split`, `train --task binary/appraisal`, `test [--zero-shot]`, `compare` |
| `run_all.sh` | The whole run in one go |
| `outputs/ft_split.csv` | Train / val / test / removed per sentence |
| `outputs/train_log_*.csv` | Loss and val scores per epoch |
| `outputs/test_finetuned/predictions.csv`, `outputs/test_zeroshot/predictions.csv` | Test predictions for each sentence |
| `outputs/test_results.csv`, `test_significance.csv` | The comparison above |
| `Figures/` | Fine-tuning figures and `fine_tuning_results.csv` (made by `../make_result_figures.py`) |

In `Final_extra/` (same path): `val_pred_*.csv` (val predictions), `test_raw_*.csv` (fine-tuned answers on the
test sentences, generated by the best-val model during `train`), `test_*/metrics.csv`, `test_results.txt` and `logs/`.

The LoRA adapters themselves (`outputs/adapter_binary`, `outputs/adapter_appraisal`, 267 MB each) are not included because of their size.

```bash
export GOLD_CSV=../Data/gold_standard_with_context.csv   # default
python finetune_llama.py split
python finetune_llama.py train --task binary
python finetune_llama.py train --task appraisal
python finetune_llama.py test
python finetune_llama.py test --zero-shot
python finetune_llama.py compare      # no GPU needed
```
